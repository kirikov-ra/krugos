# Готовые головоломки — KRG-004

`SudokuPuzzle` описывает только givens и их структурную корректность.
`Krugos.Domain.SudokuPuzzleDefinition` содержит стабильный `PuzzleId`, исходную
`Puzzle` и canonical `Solution`. Его фабрика допускает только puzzle с ровно
одним решением; детали проверки и формата ID — в [SUDOKU_DOMAIN.md](SUDOKU_DOMAIN.md).
Definition не содержит текущую доску или другое состояние партии игрока.
Сохранённое решение избавляет потребителя от повторного поиска или угадывания эталона.

## Слои и контракт

- **Domain:** `SudokuPuzzleDefinition.Create(string puzzleId, SudokuPuzzle puzzle)` —
  создание доверенных неизменяемых данных через существующий `SudokuSolver`.
- **Application:** `ISudokuPuzzleProvider` — граница получения данных с `Count`
  и `GetPuzzle(int index)`. Индексы от `0` до `Count - 1`; индекс вне диапазона
  вызывает `ArgumentOutOfRangeException`. Индекс выбирает элемент набора,
  идентичность puzzle задаётся `PuzzleId`.
- **Infrastructure:** `BuiltInSudokuPuzzleProvider` реализует этот контракт.
  В конструкторе проверяет пять записей через фабрику; затем возвращает готовые
  неизменяемые definitions без новых поисков. Порядок, ID и содержимое постоянны.

Фабрика находится в самом domain-типе: отдельный сервис или интерфейс для
проверки не нужен. Provider не зависит от Unity UI. Domain и Application
остаются обычным C# без Unity-ссылок. Для тестирования реализации только
Editor-сборка Tests.EditMode получила явную ссылку на Infrastructure.

## Встроенный набор и происхождение

В исходном коде записаны **5 различных** конфигураций по 30 givens. Источник —
существующая внутренняя `SudokuFixtures.ClassicPuzzle` из KRG-002. Внешние
каталоги, файлы и SDK не использовались. Строки получены следующими фиксированными
преобразованиями, сохраняющими Sudoku constraints и число решений:

| ID | Преобразование внутренней fixture |
| --- | --- |
| `built-in-001` | Исходная конфигурация |
| `built-in-002` | Транспонирование строк и столбцов |
| `built-in-003` | Перестановка строк `0` и `1` внутри одного блока |
| `built-in-004` | Перестановка столбцов `0` и `1` внутри одного блока |
| `built-in-005` | Замена `1 → 2 → … → 9 → 1`, пустые клетки сохраняются |

Преобразования выполнены при подготовке констант; runtime-генерации нет.
Нули в закрытых строковых константах обозначают пустоту и преобразуются в `null`
до вызова `SudokuPuzzle.Create`. ID назначены явно и не зависят от запуска,
порядка запросов или runtime GUID; другой контент должен получать другой ID.

Это временный набор для разработки gameplay vertical slice. Пять вариантов
математически эквивалентны; разнообразие сложности не заявляется.
Generator и difficulty system отсутствуют. Также нет игровой сессии, UI,
сохранений, удалённого контента или инфраструктуры кеширования.

## Проверки

Тесты напрямую проверяют фабрику, формат и стабильность ID, отказ для нуля
и нескольких решений, точный canonical solution и сохранность givens.
Provider проверяется через Application-интерфейс: количество и различие puzzles,
уникальность и фиксированные значения ID, корректность решения каждой puzzle,
соответствие документированным преобразованиям, повторяемость между экземплярами
и независимость от порядка запросов. После заполнения отдельной доски исходные
puzzle и solution остаются неизменными. Все проверки детерминированы.

Проверка от 17.09.2026: Unity 6000.6.1f1 скомпилировала проект; полный EditMode
suite — **166/166 Passed** (124 прежних и 42 новых), без ошибок и пропусков,
код завершения — `0`. Для каждой из пяти puzzles `CountSolutions(puzzle, 2)`
вернул `1`; все ID различны. Архитектурные тесты подтвердили границы сборок
и отсутствие Unity-ссылок в Domain/Application. `Validate-Foundation.ps1`
прошёл; manifest и lock-файл пакетов не изменены.

Результат и лог находятся в игнорируемых `client/TestResults/krg-004-editmode.xml`
и `client/TestResults/krg-004-editmode.log`. Мобильные сборки не выполнялись.
KRG-005 и последующие задачи не начинались.
