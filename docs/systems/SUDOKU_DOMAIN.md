# Домен Sudoku — KRG-002

## Инварианты

Классическая доска содержит 9 × 9 клеток. Координаты строки и столбца — `0..8`,
логические значения — `1..9`. Пустота представлена `null`, а не значением `0`.
В валидной доске одинаковые значения не повторяются в строке, столбце и блоке 3 × 3.
Полностью заполненная валидная доска содержит каждое значение ровно один раз
в каждой из этих областей.

`SudokuPuzzle.Create(int?[] cells)` принимает ровно 81 клетку, построчно:
индекс `row * 9 + column`. Метод копирует данные и проверяет длину, диапазон
значений и отсутствие конфликтов между исходными givens. Неверный вход,
включая `null` вместо массива, приводит к `PuzzleValidationException`;
частично созданная puzzle наружу не возвращается. `0` во входном массиве — ошибка.
Пустая puzzle и полностью заполненная валидная puzzle разрешены.
Проверка существования и единственности решения не выполняется.

## Основные типы

Все типы находятся в `Krugos.Domain` и используют только стандартную библиотеку C#.
Границы сборки сохранены: нет ссылок на Unity, Application или внешние пакеты.

| Тип | Назначение |
| --- | --- |
| `CellPosition` | Неизменяемая структура координат с проверкой `Row` и `Column`; сравнение по значению. `default` — клетка `(0, 0)`. |
| `SudokuValue` | Неизменяемая структура для `1..9` со сравнением по значению; число доступно через `Value`. Внутреннее смещение делает `default(SudokuValue)` корректным значением `1`; пустота — `SudokuValue?` со значением `null`. |
| `SudokuPuzzle` | Неизменяемая исходная конфигурация. `GetGiven` возвращает исходное значение или `null`, `IsGiven` проверяет принадлежность к givens. |
| `SudokuBoard` | Изменяемое текущее состояние одной игры, созданное из puzzle. Каждая доска владеет своим массивом значений; исходная `Puzzle` доступна только для чтения. |
| `SudokuConflict` | Флаги `None`, `Row`, `Column`, `Box`; одновременно могут присутствовать несколько конфликтов. |
| `PuzzleValidationException` | Явная доменная ошибка создания некорректной puzzle. |

Некорректные аргументы конструкторов `CellPosition` и `SudokuValue` вызывают
`ArgumentOutOfRangeException`. Конструктор доски отвергает `null` puzzle через
`ArgumentNullException`.

## Givens, ввод и проверки

Непустые клетки исходной puzzle всегда являются **givens**. Изначально пустые
клетки всегда **editable**, даже после ввода значения. `GetValue` возвращает
текущее значение, `IsGiven` — неизменяемый статус клетки.

`SetValue` устанавливает или заменяет значение editable-клетки, `ClearValue`
очищает её. Повторная очистка пустой editable-клетки разрешена. Любая попытка
записи в given, включая установку того же значения или очистку, вызывает
`InvalidOperationException` без изменения состояния.

Доска допускает конфликтующие пользовательские значения: это игровое состояние,
которое можно показать и исправить. `SetValue` не требует предварительной проверки
Sudoku constraints. Для проверки доступны:

- `GetConflicts(position)` — конфликты текущего значения; для пустой клетки — `None`.
- `GetConflicts(position, value)` — конфликты предполагаемого значения со строкой,
  столбцом и блоком. Сама целевая клетка исключена, поэтому проверка подходит
  и для замены. Метод работает также для givens, не изменяя доску.
- `IsPlacementValid(position, value)` — `true`, если клетка editable и предлагаемое
  значение не конфликтует с её соседями. Посторонний конфликт в другой области
  не запрещает локально допустимый ход. Это не проверка разрешимости puzzle.
- `GetCandidates(position)` — снимок значений в порядке `1..9`, удовлетворяющих
  локальным ограничениям пустой editable-клетки. Для given или заполненной клетки
  возвращается пустой список. Список только для чтения; последующие ходы его не меняют.
  У пустой клетки может не быть кандидатов, даже если givens не конфликтуют.
- `IsComplete` — `true` только при заполнении всех 81 клеток без конфликтов
  строк, столбцов и блоков. Заполненная невалидная доска не завершена.

Изменение доски не меняет исходную puzzle или другие доски, созданные из неё.
Модель рассчитана на последовательные обращения; синхронизация потоков не добавлена.

## Границы задачи

Животных в Domain нет: они являются визуальным соответствием логическим значениям.
Будущий mapping `значение → животное` относится к Presentation/Application и не
влияет на правила Sudoku.

В KRG-002 не входят solver/generator, проверка существования или единственности
решения, UI и view-модели, Unity-компоненты и сериализация, timer, lives, hints,
notes, difficulty, scoring, progression, сохранение и backend. Репозитории,
сервисы, event bus и другие абстракции для будущих систем не вводятся.

## Проверки

EditMode-тесты используют две фиксированные puzzle с соответствующими решениями,
а также пустые и специально конфликтующие конфигурации. Нули встречаются только
в строках тестовых fixtures: тестовый парсер преобразует их в `null` до вызова API.
Случайная генерация не используется.

Проверяются диапазоны и значения по умолчанию, строгий ввод, неизменяемость givens,
независимость досок, установка/замена/очистка, виды и комбинации конфликтов,
границы всех девяти блоков, candidates и критерий завершения. В общий запуск
входят также четыре архитектурных теста KRG-001.

Команды статической проверки и полного запуска Unity EditMode приведены в
[FOUNDATION.md](../architecture/FOUNDATION.md). Статическая проверка не заменяет
Unity-компиляцию и тесты.

Проверка KRG-002 от 17.09.2026: Unity 6000.6.1f1 скомпилировала проект;
полный EditMode-запуск — **85/85 Passed** (81 новый тест и 4 архитектурных),
ошибок и пропусков нет, код завершения редактора — `0`. Статическая проверка
`Validate-Foundation.ps1` также прошла. Ссылки на Unity отсутствуют как в DLL
Domain, так и во входных ссылках компилятора; manifest, lock-файл и `.asmdef`
не изменены. Результат и лог находятся в игнорируемых файлах
`client/TestResults/krg-002-editmode.xml` и `client/TestResults/krg-002-editmode.log`.
Мобильные сборки в рамках KRG-002 не выполнялись.
