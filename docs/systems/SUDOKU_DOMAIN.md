# Домен Sudoku — KRG-002 / KRG-003 / KRG-004

## Инварианты

Классическая доска содержит 9 × 9 клеток. Координаты строки и столбца — `0..8`,
логические значения — `1..9`. Пустота представлена `null`, а не значением `0`.
В валидной доске одинаковые значения не повторяются в строке, столбце и блоке 3 × 3.
Полностью заполненная валидная доска содержит каждое значение ровно один раз
в каждой из этих областей.

`SudokuPuzzle.Create(int?[] cells)` принимает ровно 81 клетку, построчно:
индекс `row * 9 + column`. Метод копирует данные и проверяет длину, диапазон
значений и отсутствие конфликтов между исходными givens. Неверный вход,
включая `null` вместо массива, приводит к `PuzzleValidationException`;
частично созданная puzzle наружу не возвращается. `0` во входном массиве — ошибка.
Пустая puzzle и полностью заполненная валидная puzzle разрешены.
Проверка существования и единственности решения не выполняется.

## Основные типы

Все типы находятся в `Krugos.Domain` и используют только стандартную библиотеку C#.
Границы сборки сохранены: нет ссылок на Unity, Application или внешние пакеты.

| Тип | Назначение |
| --- | --- |
| `CellPosition` | Неизменяемая структура координат с проверкой `Row` и `Column`; сравнение по значению. `default` — клетка `(0, 0)`. |
| `SudokuValue` | Неизменяемая структура для `1..9` со сравнением по значению; число доступно через `Value`. Внутреннее смещение делает `default(SudokuValue)` корректным значением `1`; пустота — `SudokuValue?` со значением `null`. |
| `SudokuPuzzle` | Неизменяемая исходная конфигурация. `GetGiven` возвращает исходное значение или `null`, `IsGiven` проверяет принадлежность к givens. |
| `SudokuBoard` | Изменяемое текущее состояние одной игры, созданное из puzzle. Каждая доска владеет своим массивом значений; исходная `Puzzle` доступна только для чтения. |
| `SudokuSolver` | Статические операции решения и ограниченного подсчёта решений исходной puzzle. |
| `SudokuSolution` | Неизменяемая полностью решённая доска; `GetValue(position)` возвращает непустой `SudokuValue`. Создаётся только solver'ом. |
| `SudokuPuzzleDefinition` | Неизменяемая готовая игровая puzzle: стабильный `PuzzleId`, исходная `Puzzle` и её единственная `Solution`. Создаётся через проверяющую фабрику `Create`. |
| `SudokuConflict` | Флаги `None`, `Row`, `Column`, `Box`; одновременно могут присутствовать несколько конфликтов. |
| `PuzzleValidationException` | Явная доменная ошибка создания некорректной puzzle. |

Некорректные аргументы конструкторов `CellPosition` и `SudokuValue` вызывают
`ArgumentOutOfRangeException`. Конструктор доски отвергает `null` puzzle через
`ArgumentNullException`.

## Givens, ввод и проверки

Непустые клетки исходной puzzle всегда являются **givens**. Изначально пустые
клетки всегда **editable**, даже после ввода значения. `GetValue` возвращает
текущее значение, `IsGiven` — неизменяемый статус клетки.

`SetValue` устанавливает или заменяет значение editable-клетки, `ClearValue`
очищает её. Повторная очистка пустой editable-клетки разрешена. Любая попытка
записи в given, включая установку того же значения или очистку, вызывает
`InvalidOperationException` без изменения состояния.

Доска допускает конфликтующие пользовательские значения: это игровое состояние,
которое можно показать и исправить. `SetValue` не требует предварительной проверки
Sudoku constraints. Для проверки доступны:

- `GetConflicts(position)` — конфликты текущего значения; для пустой клетки — `None`.
- `GetConflicts(position, value)` — конфликты предполагаемого значения со строкой,
  столбцом и блоком. Сама целевая клетка исключена, поэтому проверка подходит
  и для замены. Метод работает также для givens, не изменяя доску.
- `IsPlacementValid(position, value)` — `true`, если клетка editable и предлагаемое
  значение не конфликтует с её соседями. Посторонний конфликт в другой области
  не запрещает локально допустимый ход. Это не проверка разрешимости puzzle.
- `GetCandidates(position)` — снимок значений в порядке `1..9`, удовлетворяющих
  локальным ограничениям пустой editable-клетки. Для given или заполненной клетки
  возвращается пустой список. Список только для чтения; последующие ходы его не меняют.
  У пустой клетки может не быть кандидатов, даже если givens не конфликтуют.
- `IsComplete` — `true` только при заполнении всех 81 клеток без конфликтов
  строк, столбцов и блоков. Заполненная невалидная доска не завершена.

Изменение доски не меняет исходную puzzle или другие доски, созданные из неё.
Модель рассчитана на последовательные обращения; синхронизация потоков не добавлена.

## Solver и canonical solution

`SudokuSolver` работает с `SudokuPuzzle`, без изменения её givens и без учёта
ввода на пользовательской `SudokuBoard`. API KRG-002, включая `SetValue`, не меняется.

| Операция | Результат |
| --- | --- |
| `TrySolve(puzzle, out SudokuSolution solution)` | `true` и canonical solution; при отсутствии решения — `false` и `null`. |
| `HasSolution(puzzle)` | Есть хотя бы одно полное решение; остановка после первого. |
| `HasUniqueSolution(puzzle)` | Есть ровно одно решение; остановка после второго. Для неразрешимой puzzle — `false`. |
| `CountSolutions(puzzle, maxCount)` | Минимум фактического числа решений и `maxCount`. Достижение лимита означает «не меньше лимита», а не точное число. |

`null` puzzle вызывает `ArgumentNullException`; неположительный `maxCount` —
`ArgumentOutOfRangeException`. Лимит не задаёт размер выделяемого массива.
Операции не кешируют результаты; каждый вызов владеет отдельным состоянием поиска.

Алгоритм — backtracking с **minimum remaining values (MRV)**: следующей выбирается
пустая клетка с наименьшим числом кандидатов. Занятые значения строки, столбца и
блока хранятся в девятибитовых масках. Клетка без кандидатов немедленно отсекает
ветку. При равенстве числа кандидатов выбирается первая клетка в построчном
порядке, значения перебираются от `1` до `9`. Случайности нет. После рекурсивного
вызова восстанавливаются клетка и все три маски, затем проверяется лимит;
достижение лимита прекращает поиск на всех уровнях рекурсии.

**Canonical solution** — первое решение в этом детерминированном порядке поиска.
Оно копируется в неизменяемый `SudokuSolution` до отката состояния. При уникальном
решении это единственно возможная доска. При нескольких решениях это выбранный
эталон: отличающееся от него значение может входить в другое корректное решение.
Canonical solution не означает лексикографический минимум; изменение порядка
поиска в будущей версии может изменить выбор для неоднозначной puzzle.

Разделены три проверки:

- **Structural validity**: формат, диапазоны и отсутствие конфликтов givens.
  Дешёвая проверка в `SudokuPuzzle.Create`; не запускает поиск.
- **Solvability**: возможность дополнить givens до полной корректной доски.
  Структурно валидная puzzle может быть неразрешимой.
- **Uniqueness**: существование ровно одного полного решения.
  Проверяется отдельной операцией, не условием создания puzzle.

**Legal placement** (`board.IsPlacementValid`) проверяет только локальные
ограничения текущей доски и editable-статус. Соответствие canonical solution
проверяется сравнением значения с `solution.GetValue(position)`. Например,
в классической fixture KRG-002 значение `1` в `(0, 2)` локально допустимо,
но canonical value — `4`. Доска по-прежнему принимает как такой ввод, так и
конфликтующие значения; solver не запрещает ошибки пользователя.

Ограничения: только классическое Sudoku 9 × 9, синхронный поиск без отмены,
без сохранения всех решений и без гарантий времени на произвольном входе.
Глубина рекурсии ограничена 81 пустой клеткой. Большой лимит на очень разреженной
puzzle может потребовать длительного перебора; для проверки уникальности достаточно `2`.

## Готовая игровая puzzle

`SudokuPuzzle` остаётся структурной математической конфигурацией givens:
она может иметь ноль, одно или несколько решений. `SudokuPuzzleDefinition`
объединяет её со стабильным ID и canonical solution, гарантируя ровно одно решение.
Состояние ввода игрока в definition не хранится.

`SudokuPuzzleDefinition.Create(puzzleId, puzzle)` проверяет аргументы,
получает решение через `SudokuSolver.TrySolve` и подтверждает единственность
через `HasUniqueSolution`. Неразрешимая или неоднозначная puzzle вызывает
`PuzzleValidationException`. Конструктор закрыт; передать произвольное решение
в обход проверки нельзя. Исходная puzzle не меняется. Два поиска позволяют
сохранить API solver без изменений и дублирования алгоритма.

`PuzzleId` — неизменяемая строка формата `[a-z0-9]+(-[a-z0-9]+)*`:
непустые сегменты из ASCII-цифр и строчных латинских букв, разделённые одиночным
дефисом. Значение сохраняется точно, без нормализации и генерации GUID.
Некорректный ID вызывает `ArgumentException`, `null` ID или puzzle —
`ArgumentNullException`. Стабильность назначенного ID обеспечивает источник
контента; фабрика не ведёт глобальный реестр идентификаторов.

Canonical solution хранится, чтобы будущая игровая сессия сразу получила
достоверный эталон и не запускала solver самостоятельно. Все три свойства
только для чтения; `SudokuPuzzle` и `SudokuSolution` уже неизменяемы.
Контракт получения и встроенный набор описаны в [PUZZLE_CONTENT.md](PUZZLE_CONTENT.md).

## Границы задачи

Животных в Domain нет: они являются соответствием логическим значениям.
Mapping `SudokuValue ↔ AnimalId` реализован в чистом Application (KRG-006)
и не влияет на правила Sudoku. Контракт — в [ANIMAL_SYMBOLS.md](ANIMAL_SYMBOLS.md).

За пределами KRG-004 остаются generator, gameplay session, UI и view-модели,
Unity-компоненты и сериализация, timer, lives, hints,
notes, difficulty, scoring, progression, сохранение и backend. Репозитории,
сервисы, event bus и другие абстракции для будущих систем не вводятся.

## Проверки

EditMode-тесты используют две фиксированные puzzle с соответствующими решениями,
а также пустые и специально конфликтующие конфигурации. Нули встречаются только
в строках тестовых fixtures: тестовый парсер преобразует их в `null` до вызова API.
Случайная генерация не используется.

Проверяются диапазоны и значения по умолчанию, строгий ввод, неизменяемость givens,
независимость досок, установка/замена/очистка, виды и комбинации конфликтов,
границы всех девяти блоков, candidates и критерий завершения. В общий запуск
входят также четыре архитектурных теста KRG-001.

Тесты KRG-003 дополнительно проверяют точные canonical solutions, полные доски,
неразрешимость с немедленным тупиком и без начальных пустых списков кандидатов,
точно два решения, пустую доску, одну given в последней клетке, каждую из 81
единственной пропущенной клетки, сложную puzzle и puzzle с 17 givens.
Проверяются ограничение подсчёта, стабильность canonical solution, независимость
результатов, неизменность исходной puzzle и пользовательского ввода. Каждая
область решения проверяется на полный набор `1..9`, givens — на сохранность.
Диагностика выполняет 35 ограниченных поисков по фиксированному набору и выводит
время, но не связывает успешность теста с миллисекундами.

Команды статической проверки и полного запуска Unity EditMode приведены в
[FOUNDATION.md](../architecture/FOUNDATION.md). Статическая проверка не заменяет
Unity-компиляцию и тесты.
